# StockPilot

## 워커 관측·격리 성능 시험 준비 (2026-10-28)

- 운영자 전용 `/operations/workers`에서 최근 워커 응답과 **가격 알림·보호주문·정기매수 점검**의 성공 시각·소요 시간·실패/지연 상태를 구분합니다. 서버 Google 계정 허용 목록을 그대로 사용하며 개인 계좌·예외 원문은 제공하지 않습니다. 관측 저장 실패가 기존 작업을 막지 않도록 분리했습니다.
- `GET /api/operations/workers`는 `no-store`이며, 워커 `/` 탐침은 가벼운 생존 응답을 제공합니다. 생존·DB 준비·점검 성공·실제 체결/푸시 수신은 서로 다른 상태입니다. 여러 워커 전체의 인스턴스 수나 KIS WebSocket 복구 완료를 보증하지 않습니다.
- 미국 공시 목록은 기존 공급 범위인 최대 8건을 표시하고 중복 서식명은 읽기 쉬운 한국어와 함께 표시합니다. 공시 행·날짜·원문 접근은 기존 색상과 라이트/다크 모드를 유지하며 모바일에서 재배치합니다.
- `compose.capacity.yaml`은 **운영과 분리된 PostgreSQL·Redis·API·워커 + k6**의 첫 단계 시험 구성입니다. 운영 자격증명·외부 시세 API를 차단하며 실제 금융 거래 처리량과 구분합니다. 현재 PC에는 Docker 실행 환경이 없어 컨테이너 기동·부하 수치는 아직 미검증입니다.

실행 방법, 준비할 서버와 비용·목표·관측 기준은 [워커·성능 시험 가이드](docs/worker-capacity-20261028.md)에 있습니다. 백엔드 회귀 261개·프론트 안전성 15종·타입/빌드를 로컬에서 검증했습니다. 코드 검증과 운영 배포 완료·대규모 부하 통과는 별개입니다. 기존 계좌·주문 금액 계산·앱인토스 번들은 유지합니다.

## 미국 공시·격리 부하 검증 (2026-10-27)

- 미국 기업정보는 **SEC EDGAR의 실제 제출 이력**을 사용합니다. 별도 API 키 없이 서버의 `SEC_USER_AGENT`에 운영자 식별·연락처를 설정합니다. 연락처 원문은 저장소·브라우저에 넣지 않습니다.
- 공시는 기업 CIK 기준 공유 캐시(15분), 종목 목록 캐시(24시간), 동일 조회 합치기, 전체 API replica 간 요청 간격 제한(기본 2회/초)을 사용합니다. Redis가 설정됐지만 사용할 수 없으면 각 서버가 제각각 외부 요청을 보내지 않습니다. 403·429와 `Retry-After`를 존중하고 실패·미설정 결과는 공개 캐시하지 않습니다.
- 미국 종류주 `BRK/B`·`BRK.B`는 **SEC 목록에 실제 존재하는 `BRK-B`**로 기업 식별만 해석합니다. 화면·시세·주문의 원본 종목 식별자는 보존합니다. 잘못된 CIK·제출일·원문 경로는 출력하지 않으며 정정 제출(`/A`)도 포함합니다.
- `load_capacity.py`는 운영 도메인을 차단하고 격리 대상 확인 후 읽기 요청만 보냅니다. 단계별 목표/실제 RPS, p50/p95/p99, 실패율, 생성기 누락을 따로 기록하며 무한 대기열·자동 재시도·외부 시세 API 부하를 만들지 않습니다. 기존 `load_smoke.py`도 이 안전 실행기로 연결합니다.
- **실행 결과와 한계:** 로컬 합성 공시 읽기 시험에서 25·50 RPS 단계는 통과했으나, 100 RPS 단계는 생성기가 목표 요청량을 달성하지 못해 중단했습니다. PostgreSQL·Redis·실제 주문·WebSocket·실사용자 4만 명 수용량은 검증되지 않았습니다. 실제 공시 3개 기업의 로컬 조회와 운영 배포 여부도 구분합니다.

명령·수치·후속 시험 조건은 [SEC·부하 검증 기록](docs/sec-load-verification-20261027.md)에 있습니다. 기존 웹 디자인·계좌·주문 계산·앱인토스 번들은 변경하지 않습니다.

## 국내·미국 전체 종목 탐색

- **시장 상단의 `전체 종목`**에서 한국 **코스피·코스닥**, 미국 **나스닥·뉴욕·아멕스**의 제공 종목을 바로 검색합니다. 시가총액·거래량·상승률·하락률과 같은 패널 안에서 전환하며 별도 페이지나 아래 접힌 목록으로 이동하지 않습니다. 회사명·영문명·코드·티커 검색은 현재 보이는 20개가 아닌 선택한 시장의 전체 목록을 대상으로 합니다. 순위 API의 상위 종목과 전체 목록의 데이터 범위는 구분합니다.
- 상단 메뉴·빠른 검색 바로가기·모바일 전체 메뉴도 같은 시장 내 검색으로 연결합니다. 기존 `/stocks?market=US&exchange=NYS&q=...&page=...` 북마크는 조건을 보존해 통합 화면으로 이동합니다.
- **20/50/100개 단위**, 이전·다음·마지막 페이지, 페이지 직접 이동을 지원합니다. 탐색 방식·국가·검색·거래소·페이지를 URL에 보관해 새로고침·뒤로가기와 종목 상세의 `시장으로 돌아가기`에서 복원합니다. 전체 목록의 국가·조건은 선택한 종목의 시장·거래소와 별도 필드로 저장하므로 미국 종류주 등 원본 식별자를 바꾸지 않습니다. 수만 행을 한 번에 내려보내거나 종목 전체의 시세를 동시에 요청하지 않습니다.
- 종목 행은 기존 **실제 시세·차트·관심종목·모의주문 상세**로 연결합니다. 데이터가 없는 종목의 가격을 만들지 않습니다. 목록 수신 시각과 시세 시각은 구분합니다.
- 공식 KIS 마스터의 **코스피/코스닥 필드 길이 차이**, 영문이 포함된6자리 코드,9자리 펀드 식별자 오인 문제를 수정했습니다. 동일 코드 검증을 검색·비교·공시 경로에 적용합니다. 기존 계좌·주문 계산·실제 거래 여부는 변경하지 않습니다.
- 미국 종류주·우선주 등의 `/` 포함 티커는 원본 그대로 URL에 인코딩해 상세·비교·기업정보 조회로 전달합니다. 다른 티커로 치환하거나 시세를 임의 생성하지 않습니다. 제공되지 않는 시세·기업정보는 미제공 상태로 구분합니다.
- **시세 응답 경합 보완**: 늦은 기본 시세 목록·로컬 캐시가 상세에서 조회한 종목을 지우지 않게 종목ID·수신 자료 시각으로 병합합니다. 미국 종목은 시세 조회 전에도 통화·거래소를 원본 식별자로 표시하며, 직접 URL 조회 실패는 지속적인 오류 안내와 재조회·다른 종목 찾기를 제공합니다. 모의주문은 여전히 검증된 시세가 있어야 가능합니다.
- 2026-10-27 공식 파일 확인 기준 **국내3,953개 / 미국12,882개**입니다. 고정된 상품 개수나 모든 금융상품의 지원을 보장하는 수치가 아닙니다. 목록은 서버가 공식 마스터를 수신한 기준이며 선물·옵션·장외주식 등은 이 범위가 아닙니다. 거래정지·시세 미제공 종목은 모의주문이 불가능할 수 있습니다.
- 일부 거래소 수신 실패는 ‘전체’로 숨기지 않고 경고와 수신 상태를 표시합니다. 목록 버전이 바뀌면409로 재탐색을 안내하고, 통신 실패는 재조회할 수 있습니다. 없는 값은0으로 바꾸지 않습니다.

읽기 전용 API: `GET /api/market/instruments?market=KR&exchange=ALL&limit=20&offset=0&q=`. `limit`는20/50/100, `offset`는0~50,000, 검색어는최대80자입니다. 결과의 `snapshot`으로 목록 버전을 고정하며 `total`은 검색 결과 수, `universeTotal`은 선택한 시장·거래소 목록 수입니다. 검색 응답은 공유 캐시하지 않습니다. 신규 키·DB 마이그레이션은 필요하지 않으며 기존 앱인토스 번들은 변경하지 않습니다.

검증: `cd backend && .venv/Scripts/python.exe -m pytest unit_tests -q -p no:cacheprovider`, 프론트의 `node scripts/verify-stock-directory.cjs`, `node scripts/verify-integrated-directory.cjs`, `pnpm run verify:safety`, `node scripts/verify-product-edition.cjs`, 타입·린트·프로덕션 빌드를 실행합니다. 로컬 격리 화면은 `UPGRADE_FIXTURE=1 PORT=5265 node scripts/preview-functional.mjs`; 실제 계좌/운영 서버와 연결하지 않습니다. 새 버전 공개는 사용자 승인 후 upstream→실제 fork 동기화→코더스 배포→운영 확인 순서로 진행합니다.

## 2026-10-27 · 더 편한 종목 탐색과 확대 차트

**코더스 웹 전용 업데이트**입니다. 기존 계좌·인증·모의주문 계산과 별도 앱인토스 번들은 유지합니다. 돈만 연습용이며, 이 변경으로 실제 주문을 보내거나 시세를 생성하지 않습니다.

- **집중된 시장 화면**: 지수와 원화 평가 자산을 간결하게 배치하고 검색·종목 목록을 먼저 보여줍니다. 모바일에서도 자산과 주문 가능 원화·달러를 확인할 수 있습니다. 389px 이하에서는 금액과 주문 가능 메뉴를 다른 행에 놓아 숫자 끝자리가 떨어지지 않도록 합니다. 기능 안내·보조 메뉴는 아래로 정리하며 기존 목적지는 유지합니다.
- **불러온 목록 필터**: 회사명·코드·거래소, 관심종목, 가격 범위, 상승·하락·보합 조건을 조합합니다. 한국/미국 전환 시 가격 단위를 초기화하며, 필터 후에도 원래 순위와 계속 불러오기를 유지합니다. 목록 한눈에는 **현재 불러온 종목만** 집계하며 전체 시장의 상승·하락 통계나 개인화 추천이 아닙니다.
- **확대 차트**: 종목 상세의 `넓게 보기`에서 선·일봉·MA20, 거래량, 확대·축소·이동, 키보드 날짜 선택을 이용합니다. 기존 일별 시세만 사용하고 누락된 날짜·거래량을 만들지 않습니다. 유효한 OHLC가 없으면 일봉 대신 종가 선을 사용하며, 기본 SVG 차트와 접근 가능한 표도 유지합니다. 실시간 틱 차트는 아닙니다.
- **비교 동선**: 실제 종목 2~3개를 고르고 하단 비교 버튼으로 이동합니다. 비교 링크에는 공개 종목 식별자만 담으며 계좌·보유 정보는 넣지 않습니다.
- **표시·조회 복구**: 기본 다크 테마는 첫 화면부터 적용하고, 사용자가 저장한 라이트/금액 숨김/밀도 설정은 존중합니다. KOSPI 조회는 제한시간·취소·응답 검증·수동 재조회를 지원하며, 실패 시 이전 자료와 확인 시각을 유지합니다. 저장소 사용이 차단되어도 조회를 중단하지 않습니다.

프레임워크는 Next.js 16·React 19, 기존 Pretendard·Lucide·API를 유지합니다. 확대 화면을 열 때만 `lightweight-charts@5.2.1`을 지연 로드합니다. 이는 차트 렌더링 라이브러리이지 TradingView 시세 연동이 아닙니다. Apache-2.0/MIT 고지와 링크는 [오픈소스 안내](THIRD_PARTY_NOTICES.md)에 있습니다. 새 API 키·유료 플러그인·DB 마이그레이션은 필요하지 않습니다.

검증: `cd frontend && pnpm run verify:safety && pnpm run verify:product && pnpm exec tsc --noEmit && pnpm build --webpack`. 로컬 UI 검증은 `UPGRADE_FIXTURE=1 PORT=5264 node scripts/preview-functional.mjs`의 **격리된 검증 자료**를 사용하며 운영 계좌에 시험 주문을 쓰지 않습니다. 최신 점검 범위와 실제 운영 확인은 [디자인·기능 검증 기록](docs/web-design-qa-20261027.md)을 참고하세요.

## 2026-10-25 · 페이지 전반 안정성·관심종목 배치 보완

기존 디자인·다크/라이트 테마·계좌 데이터·모의주문 규칙은 유지하는 **코더스 웹 전용** 보완입니다. 앱인토스 번들과 검토 상태는 변경하지 않습니다.

- **폭에 맞는 관심종목**: 좁은 데스크톱 사이드 패널과 넓은 관심 화면을 컨테이너 기준으로 구분합니다. 검색, 시장·정렬, 표시 개수·초기화를 각각 정렬하고 회사명·가격·등락률·별 버튼이 밀리지 않도록 보완했습니다. 최근 본 종목도 검색 영역 전체 폭을 사용합니다.
- **저장 결과의 정확성**: 브라우저 관심종목 가져오기는 실제 저장된 개수만 안내하고, 일부 실패 시 멈춰 기존 브라우저 기록을 보존합니다. 저장 전에 시작한 늦은 조회가 새 저장·삭제 결과를 덮어쓰지 않도록 합니다.
- **리그·라운지·성장·뉴스·기업정보 복구**: 요청 제한시간과 취소, 실패·빈 자료 구분, 이전 결과 유지 및 수동 재조회를 보완했습니다. 실패를 ‘자료 없음’으로 표시하거나 무한 로딩하지 않도록 합니다. 뉴스는 5분 주기를 유지하고, 제공되지 않은 갱신 시각을 임의로 만들지 않습니다.
- **과거 투자 연습 안전성**: 종목 변경 중 이전 종목의 가격·통화로 매매하지 못하도록 차단하고, 1~10,000주 정수 수량을 검증합니다. 과거 시세의 종목·날짜·종가/OHLCV를 검증하고 누락값은 `—`로 표시합니다. 이는 별도 학습 계좌이며 실제 모의투자 계좌 금액·거래 규칙을 변경하지 않습니다.

## 2026-10-25 · 증권형 종목 탐색·상세 분석

구현·자동 검사를 완료했습니다. 저장된 브라우저 접근 정책으로 실화면 검증은 수행하지 못했으며, 이 제약을 알린 뒤 받은 사용자의 최신 지시에 따라 배포합니다. 모바일·데스크톱 시각 검증까지 통과했다는 의미는 아닙니다. 실제 운영 반영 상태는 코더스 배포 이력과 릴리스 결과를 기준으로 확인하세요.

실제 시세를 살펴보고 비교한 뒤 모의주문으로 이어지는 웹 흐름을 보완했습니다. 기존 계좌·주문 규칙·브랜드와 별도 앱인토스 버전은 유지합니다.

- **순위에서 바로 비교**: 국내·미국 순위에서 공개 종목 2~3개를 골라 기존 비교 화면으로 이동합니다. 시장 전환/더보기에도 선택을 유지하며, 비교 URL에는 계좌·잔고·개인 메모를 넣지 않습니다.
- **모바일 순위 지표**: 시가총액·거래량을 작은 화면에서도 라벨과 함께 확인합니다. 상세 열기, 관심 저장, 비교 선택을 각각 독립된 조작으로 구분합니다.
- **실제 일별 시세 차트**: 선/일봉 전환, 거래량 막대, 선택 거래일의 시가·고가·저가·종가와 표 대체를 제공합니다. OHLC가 불완전한 자료는 가짜 봉으로 보충하지 않습니다. 최대 80거래일 자료이며 분봉·실시간 틱·1년 차트가 아닙니다.
- **미국 종목 핵심 지표**: 기존 미국 전용 `quote-details` API를 웹 상세에 연결해 시가총액, 상장 주식 수, PER/PBR, 당일·52주 가격 범위를 제공합니다. 확인되지 않는 값은 `—`로 표시하고 지표 오류는 주문 화면과 분리해 재조회합니다. 한국 종목의 52주 값을 짧은 일별 자료로 추정하지 않습니다.
- **기능 접근성**: 시장 홈의 비교·알림·계좌 도구·매매 기록 바로가기를 추가했습니다. 기존 색상·글꼴·금액 단위와 라이트/다크 테마를 재사용합니다.

추가 API 키·DB 마이그레이션·유료 프론트 라이브러리는 없습니다. 기존 `GET /api/features/history`, `GET /api/trading/quote-details`, 순위·검색·비교 계약을 재사용합니다. 실제 호가 잔량/체결 틱/투자자 수급/애널리스트 컨센서스와 추천·개인 인기 순위는 이번에 새로 제공하지 않습니다. 해당 기능은 공급 API·데이터 이용 범위를 먼저 확인해야 합니다.

참고한 공식 공개 구조: [Npay 증권](https://stock.naver.com/), [토스증권](https://www.tossinvest.com/). 미래에셋 공개 페이지는 본문을 추출하지 못했고, 외부 참고 사이트의 브라우저 열기 권한이 허용되지 않아 실제 시각 비교를 수행했다고 주장하지 않습니다. 타사 자산·폰트·화면은 복제하지 않습니다. 이번 설계는 `design.md`의 ‘증권 서비스형 탐색과 종목 상세’를 따릅니다.

**검증:** backend의 `tests/test_personal_tools.py`는 운영 DB가 아닌 메모리 SQLite + ASGI로 계정 분리·버전 충돌·멱등 요청·환전 잔고/수익률·만료·정기 주문·잔액 부족·배당/분할·운영 권한을 확인합니다. PostgreSQL 동시성/실제 4만 명 부하 시험과 동일한 검증은 아닙니다. `PERSONAL_FIXTURE=1`로 켜는 `backend/scripts/preview_personal.py`(5234)와 `frontend/scripts/preview-functional.mjs`(5232)는 로컬 격리 UI 검증 전용이며 운영 연결이 없습니다.

## 2026-10-14 · 출시 안정성 보완

- **잔고 조회 상태**: 실패 시 마지막 잔고를 유지하고 조회 시각·재조회 버튼을 표시합니다. 최신 계좌 응답을 검증하기 전에는 새 모의 주문과 보호 주문 생성을 막습니다. 겹치는 잔고 요청은 같은 진행 중 요청을 공유합니다.
- **주문 결과 보관**: 일회성 토스트뿐 아니라 체결·접수 대기·거절·취소 결과와 주문 번호 일부를 화면에 남깁니다. HTTP 성공을 체결 완료로 간주하지 않습니다.
- **응답 유실 복구**: `GET /api/trading/orders/request/{request_key}`는 로그인한 사용자의 요청만 읽으며 새 주문을 만들지 않습니다. 조회가 404여도 처리 중일 수 있으므로 미접수라고 단정하지 않습니다. 같은 화면에서 사용자가 원래 주문 재전송을 선택하면 원래 내용·동일 Idempotency-Key를 사용합니다. 연결 복구·타이머는 주문을 자동 재전송하지 않습니다.
- **새로고침 뒤 확인**: 탭의 sessionStorage에는 계정 식별자와 미확인 요청 번호만 남깁니다. 잔고·주문 내용·인증정보는 저장하지 않으며, 화면을 다시 열면 결과 조회만 제공합니다. 새 주문 준비는 이전 주문을 취소하지 않습니다. 저장소가 차단되면 현재 화면의 메모리 복구만 가능합니다.
- **잘못된 자료 차단**: 비정상 금액·통화·시각·종목 식별자·주문 응답을 검증합니다. 시세 및 계좌 요청은 제한시간을 두고 끝내며, 오래된 로컬 시세를 실시간 수신으로 표시하지 않습니다. 저장 공간 부족·비공개 모드에서도 최근 종목 선택이 화면 오류를 만들지 않습니다.

검증 명령: frontend에서 `pnpm verify:safety`, `pnpm build`; backend에서 `.venv/Scripts/python.exe -m pytest unit_tests/test_order_request_lookup.py unit_tests/test_order_validation.py -q -p no:cacheprovider`. `frontend/scripts/preview-functional.mjs`는 운영 연결 없는 로컬 fixture이며 `release_case`로 응답 유실·거절·잔고 실패를 재현합니다. 운영 계좌로 주문을 만들어 테스트하는 도구가 아닙니다.

이 보완은 장애·시세 제공자 중단·실기기 차이의 부재를 보증하지 않습니다. 공개 사용자 확대 전에는 별도 테스트 계정의 주문/취소 회귀 검증, 실제 iPhone·Android 검사, 운영 로그/백업 복구 점검, 실제 동시 사용자 부하 검사와 시세 이용 범위 확인이 필요합니다. 가상 주문·원장 규칙, 기존 데이터와 앱인토스 비공개 소스는 변경하지 않습니다.

## 2026-10-13 · 디자인을 유지한 탐색·기록 개선

### 별도 종목 비교 페이지

[/compare](https://stockpilot.coders.kr/compare)에서 한국·미국 종목을 최대 3개 선택해 현재가와 1주·1개월·3개월의 공통 날짜 종가 변화를 비교할 수 있습니다. 각 종목의 같은 시작일을 0%로 맞추고 기간 가격 변화·고점 대비 최대 하락폭을 계산합니다. 배당·수수료·환율 효과는 제외하며, 시장별 종가 시점이 다르다는 점을 표시합니다. 자료가 없거나 공통 날짜가 부족하면 수치를 만들지 않습니다.

비교 목록과 1,200자 개인 메모를 브라우저에 최대 10개까지 저장할 수 있습니다. 공유 링크는 종목 식별자만 포함하며 메모·계좌 정보는 포함하지 않습니다. 저장 목록을 열면 시세를 새로 조회합니다. 홈의 더 많은 투자 기능, 빠른 검색 바로가기, 모바일 전체 메뉴에서 진입할 수 있으며 기존 화면의 색 토큰·폰트·카드·라이트/다크 테마를 재사용합니다.

‘같은 금액으로 시작했다면?’에서는 원화와 달러를 나눠 첫 종가에 정수 수량을 샀을 때의 평가금액·남은 현금·가격 손익을 계산합니다. 가상계좌에 주문을 넣는 기능이 아니라 비용·배당·환율을 제외한 별도 계산 연습이며, 계산 기준과 날짜를 표시합니다. 모바일 순위·관심종목 버튼의 터치 영역을 44px로 보완하고 입력창을 16px로 맞췄습니다.

가격 변화 그래프는 공통 날짜로 정렬하고, 최대 하락폭은 그 시작일~종료일 사이 각 종목의 제공된 모든 일별 종가로 계산합니다. 서로 다른 휴장일 때문에 종목의 중간 하락이 빠지지 않도록 구분합니다. 비교 계산 검증은 `frontend`에서 `node scripts/verify-comparison.cjs`로 실행합니다.

추가 점검에서는 순위 목록에 코스피·코스닥 및 나스닥·뉴욕·아멕스 거래소 필터를 연결했습니다. 순위 더 보기 요청도 화면 이동·필터 변경 시 취소하고, 다음 페이지 위치가 유효할 때만 계속 조회합니다. 판단 기록은 저장 대상 종목을 표시하고 브라우저 저장 실패 안내를 추가했습니다. 기존 종목별 메모 분리를 유지합니다. 빠른 검색은 빈 결과의 방향키 이동, 검색 오류 재시도, 키보드 선택 결과의 스크롤과 접근성 상태를 보완했습니다.

검증 명령은 `frontend`에서 `node scripts/verify-market-responses.cjs`와 `node scripts/verify-record-filters.cjs`입니다. `node scripts/preview-functional.mjs`는 `127.0.0.1:5232`에서 격리된 자료로 검색 실패·재시도·거래소 필터·메모를 확인하는 로컬 도구이며, 운영 데이터와 연결되지 않고 주문 쓰기를 거절합니다. 운영 배포에는 이 자료를 사용하지 않습니다.

화면 파일 로딩 실패는 사용자가 다시 시도를 누르면 새 페이지를 불러오도록 처리합니다. 오류 화면에서 주문 미처리를 단정하지 않고 매매 기록에서 확인하도록 안내하며, 주문을 자동으로 재전송하지 않습니다.

- 관심종목: 한국·미국 필터, 저장순·이름순·등락률 정렬. 시세가 없는 종목은 등락률 정렬의 마지막에 표시합니다. 저장은 기존처럼 브라우저별 최대 12개이며, 한도 초과 시 기존 종목을 조용히 삭제하지 않고 안내합니다.
- 투자 기록: 종목 코드·거래소 검색, 매수/매도 및 주문 상태 필터, 최신순·20건씩 더 보기. 서버에서 실제 불러온 내역만 검색하며 전체 계좌 이력을 모두 불러왔다고 표시하지 않습니다.
- 전체 종목 탐색: 화면 해제 시 진행 중 요청을 취소합니다. 기존 실시간 시세·계좌·주문 규칙·앱인토스 코드는 변경하지 않습니다.

## 2026-10-11 · Google Stitch를 바탕으로 한 반응형 리디자인

사용자가 공유한 비공개 [Google Stitch 보드](https://stitch.withgoogle.com/projects/7455637925981793042?pli=1)의 시장·종목 상세·자산·미국 시장·야간 화면을 시각 참고로 삼아 전체 UI를 다시 구성했습니다. 밝고 정돈된 시세 화면, 브랜드 블루 강조, 정보량이 분명한 종목 행, 투자 결정을 중심에 둔 상세 화면을 StockPilot의 자체 컴포넌트와 색 토큰으로 구현했습니다. 토스증권을 포함한 다른 서비스의 로고·전용 자산·화면을 복제하지 않습니다.

시안에만 있던 가상 지수, 호가 잔량, 환전 계산, AI 뉴스/추천, 자동매수·배당 재투자 등은 현재 서비스에서 실제로 지원되는 것처럼 넣지 않았습니다. 기존 KRX·NXT·미국 시세, 계좌·원장, 검색·순위, 관심종목, 모의 주문·체결 상태, 자산·기록, Google 로그인과 기존 경로는 유지합니다. 앱인토스 코드는 수정하지 않았습니다.

- 시장 홈은 요약 지수 → 탐색/검색 → 실제 순위 목록 → 개인 관심 맥락 순으로 정리합니다.
- 공통 종목 행은 회사 마크·이름·코드·시장·통화·가격·등락·지원 지표를 정렬하고, 미제공 값은 숫자 0으로 꾸미지 않습니다.
- 종목 상세는 종목 식별 → 현재 시세와 자료 시각 → 기존 차트와 회사 정보 → 명확한 모의 주문 진입 순으로 구성합니다.
- 자산·투자 기록은 기존 계좌와 실제 모의 주문 내역을 사용하며, 달러를 원화로 임의 환산하지 않습니다.
- Pretendard Variable, 명확한 탭/포커스 상태, 모바일 하단 내비게이션, 작은 화면 주문 UI, 다크 모드, reduced-motion 동작을 유지합니다.

### 앱인토스 전용 화면과 공유 시세 API

미국 시총의 필수 `CURR_GB=0` 입력을 반영하고 응답 `output1.curr=USD`를 검증합니다. 현재 제공자 응답에 연속조회 keyb가 없으면 조회된 행 수를 KEYB 오프셋에 누적하며, 반드시 `tr_cont=N`과 함께 요청합니다. 제공자 실응답으로 1~100위, 101~200위의 구분과 통합 시총/거래량 최대 600종목을 확인했습니다. 국내 등락 조회는 공식 예제대로 `FID_INPUT_CNT_1=0`에서 시작합니다. 이 수치는 공급자 상위 조회 범위이지 거래소 전체 시총 순위나 부하 수용량을 보증하는 값은 아닙니다.

앱 전용 연속 조회: `GET /api/toss-market/browse-rankings`는 필요한 다음 페이지를 공급자로부터 이어 받아 기존 600개 고정 결과 제한을 없앴습니다. `limit`은 1~100, 기본 50이며 앱에서 20·50·100개씩 선택합니다. 공급자 자료가 끝날 때까지 이어 보되 안전 상한은 50,000개입니다. 요청당 추가 공급자 호출은 거래소별 최대 3회, 공유 snapshot 캐시는 15분이며 분산 잠금과 실패 재시도 간격으로 폭주를 제한합니다. 미국 통합 순위는 각 미완료 거래소에서 확보한 공통 prefix까지만 공개해 미조회 상위 종목보다 다른 거래소 종목을 먼저 끼워 넣지 않습니다. 한국 `ALL`은 KOSPI·KOSDAQ 순위를 각각 조회해 중복을 제거하고 시가총액 기준으로 합칩니다. 따라서 한쪽 응답이 30개에서 끝나도 다른 시장 결과를 합쳐 더 볼 수 있으며, 공급자가 연속 조회를 제공하면 다음 페이지도 이어 받습니다. `total`은 현재 검증된 prefix의 개수이며 전체 거래소 종목 수가 아닙니다. 만료된 snapshot은 409와 새로고침 안내, 일시 실패는 재시도 안내를 반환합니다. 공급자 자료가 끝나면 그 범위까지만 보여주며 없는 시세나 순위를 만들지 않습니다. DB·원장·기존 웹 화면 변경은 없습니다.

호환용 `GET /api/toss-market/rankings`는 기존 고정 대표 10종목이 아닌 KIS 실제 시총·거래량·일간 상승/하락 순위를 조회합니다. 국내 ALL/KOSPI/KOSDAQ, 미국 ALL/NAS/NYS/AMS와 `offset`, `limit`(1~100)을 받습니다. 미국 ALL은 세 거래소에서 제공한 상위 자료를 같은 USD 단위로 결합하며 거래소 전체 상장 종목의 완전한 순위라고 주장하지 않습니다. 이 이전 경로는 결과 600개 상한·120초 공유 캐시·15초 요청 제한을 유지합니다. 다음 페이지에는 `snapshot`을 전달해 도중에 갱신된 순위를 섞지 않습니다. USD/원화 시총은 `가격×상장주수`와 단위를 교차검증하고 확인되지 않은 값은 제외합니다. 순위 조회 시간은 체결 시간이 아닙니다.

`GET /api/toss-market/instruments`는 KIS 종목 마스터를 시장/거래소별로 페이지 조회합니다. 웹의 **국내·미국 전체 종목** 탐색에서는 코스피·코스닥과 나스닥·뉴욕증권거래소·아멕스를 골라 20개씩 이어 볼 수 있고, 종목을 선택하면 그 종목의 시세를 조회합니다. 종목 마스터 목록 자체에는 가격이 없으므로 가격을 0원으로 표시하거나 모든 심볼의 시세를 한꺼번에 요청하지 않습니다. 서버가 필요한 마스터 파일을 모두 받지 못하면 현재 목록을 일부 자료로 표시하고 전체 목록처럼 가장하거나 페이지를 이어 보여주지 않습니다. 기존 계좌·원장·주문 동작은 바꾸지 않았습니다. 공개 시장 자료만 반환하며 계좌·개인 정보는 포함하지 않습니다.

앱인토스는 별도 비공개 저장소에서 개발하며 이 저장소의 웹 화면은 변경하지 않습니다. 앱인토스의 현재 투자 경험은 KIS 실제 시세·KOSPI와 개인별 가상원장을 사용합니다. `/api/toss-game`의 자체 생성 가상시장 코드는 별도 실험용이며 실제 시장 정보로 대체하거나 표시하지 않습니다. 시세의 다중 사용자 제공에는 개인 API 발급과 별도로 승인된 제공 범위가 필요합니다.

2026-09-30 **공유 조회 API 배포·운영 응답 확인 완료**: 미국 상세 조회 `GET /api/trading/quote-details?symbol=AAPL&market=US&exchange=NAS`. 기존 KIS 해외주식 현재가상세 `price-detail`을 읽어 당일·52주 가격 범위, PER/PBR, USD 시총을 반환합니다. `tomv` 시총을 `last × shar`와 교차검증하며 확인되지 않는 단위·비정상 수치는 null입니다. `mcap` 자본금을 시총으로 사용하지 않습니다. 기존 주문 체결용 현재가나 잔고를 변경하지 않는 선택적 API로, 공유 캐시 120초·KIS 요청 제한·6초 제한시간을 적용합니다. 호출 실패는 503과 Retry-After를 반환합니다. 추가 키·DB 마이그레이션 없이 배포했으며 AAPL·NVDA·TSLA(NAS), IBM(NYS)의 실제 USD 시총·가격 범위·PER/PBR 응답을 확인했습니다. `asOf`는 서버 조회 시각이며 거래소 체결 시각과 같다는 의미가 아닙니다. 웹 UI는 수정하지 않습니다.

검증: backend 단위 테스트 77개, 앱인토스 계산·응답 검증 테스트 20개, 운영 빌드의 실패 응답 격리 7개 시나리오 통과. 앱인토스 로컬 9개 화면 × 4개 크기 회귀 검사 및 운영 웹 360·390·768·1440px 읽기 검사 통과. 앱인토스 새 버전은 비공개 테스트 단계로 공개 출시 완료를 의미하지 않으며 실제 토스 앱 확인이 필요합니다. 전체 장애 부재·대규모 트래픽 수용량·거래소 원본값과의 독립 대조를 보증하는 검사는 아닙니다.

### 수익화 기획: 핵심 경험은 무료, 깊은 복기는 멤버십으로

StockPilot은 가상투자 서비스이므로 주문 수수료나 실거래 중개가 아니라 **반복해서 사용하는 학습 도구**를 유료화합니다. 누구나 시장 시세와 첫 가상주문을 경험할 수 있어야 유입이 커지고, 알림·복기·리포트·팀 운영처럼 사용 빈도와 업무 가치가 높은 기능에서 지속적인 매출을 만들 수 있습니다.

| 플랜 | 대상 | 제공 가치 | 상태 |
|---|---|---|---|
| **시작하기** | 모든 사용자 | KRX·NXT·미국 시세, 가상주문, 기본 리그·학습, 가격 알림 3개 | 운영 중 · 무료 |
| **Pro (월 5,900원 제안)** | 반복 훈련하는 개인 | 알림 무제한, 시장 타임머신 전체 구간, 샤프·낙폭·슬리피지 리포트, CSV/PDF 내보내기, 광고 없는 화면 | 출시 전 수요 확인 |
| **Team (월 49,000원부터 제안)** | 스터디·학교·교육기관 | 비공개 리그, 초대 코드, 참가자 대시보드, 주간 리포트, 관리자 권한과 운영 로그 | 출시 전 수요 확인 |

홈의 `Pro 플랜` 카드와 `/pricing` 페이지에서 이 구조를 설명하고, 로그인 사용자는 결제 전 출시 알림을 신청할 수 있습니다. 결제 공급자·환불 정책·서명 검증 웹훅을 연결하기 전에는 어떤 사용자도 유료 권한을 받지 않으며, 브라우저 저장값으로 Pro를 활성화할 수 없습니다. 즉 현재 배포는 **수요 검증 단계**이고 실제 과금은 운영자가 결제 요건을 확정한 뒤 별도 릴리스로 켭니다.

```text
무료 유입 → 첫 가상주문 → 반복 알림·복기 사용 → Pro 전환
                                └→ 비공개 리그 운영 → Team 도입
```

이 구조는 투자 조언·현금 상금·브로커리지 수수료에 의존하지 않고, 교육 품질과 리텐션을 높인 기능에만 가격을 붙입니다. 개인 포트폴리오나 거래내역은 판매하지 않으며, 스폰서 콘텐츠가 추가되더라도 광고임을 명확히 표시합니다.

#### 광고 수익화

웹과 TWA에서 공통으로 사용할 수 있도록 홈·뉴스·성장 허브·리그에만 반응형 광고 슬롯을 제공합니다. 주문·로그인·알림·커뮤니티 입력 화면에는 광고를 배치하지 않아 실수 클릭과 핵심 흐름 방해를 줄였습니다. 광고 계정 검토 전에는 슬롯이 렌더링되지 않으며, 자세한 설정은 [`docs/ADS_MONETIZATION.md`](docs/ADS_MONETIZATION.md)에서 확인할 수 있습니다.

### 사용자가 느끼는 5단계 여정

```text
발견  →  이해  →  연습  →  기록  →  성장
TOP 10     차트·뉴스     가상주문     일지·리포트     리그·타임머신
```

1. **발견:** 첫 화면에서 KRX·NXT·미국 시장 상태와 TOP 10을 즉시 확인합니다.
2. **이해:** 종목 검색, 가격 흐름, 뉴스, OpenDART 기업정보로 매매 전에 맥락을 읽습니다.
3. **연습:** 시장가·지정가·손절·조건부 주문을 가상원장에 제출하고 체결 품질을 확인합니다.
4. **기록:** 주문 근거와 목표를 투자일지에 남기고 거래 명세·리포트로 결과를 복기합니다.
5. **성장:** KOSPI 상대성과, 수익률 리그, 시장 타임머신에서 다음 의사결정을 훈련합니다.

### UX 설계 원칙

- **첫 화면은 판단에 필요한 것만:** 실시간 상태, 시장 기준선, 검색, 주문을 한 화면의 우선순위로 배치합니다.
- **핵심 여정을 한 줄로 안내:** 시장 읽기 → 종목 선택 → 안전 주문 → 기록·복기를 현재 상태와 함께 표시하고 각 단계로 바로 이동합니다.
- **초보자와 숙련자 화면 분리:** 핵심 투자 루프는 항상 보이게 유지하고, 시장 강도·집중도·급락 스트레스 테스트는 고급 체크업으로 접어 정보 과부하를 줄입니다.
- **위험은 행동 전에 설명:** 미보유 매도, 수량 초과, 시세 지연, 현금 부족을 접수 전에 한국어로 안내합니다.
- **모바일 우선, 입력 장치 독립:** 반응형 레이아웃과 하단 내비게이션을 제공하고, `/` 검색 단축키·포커스 표시·스킵 링크로 키보드와 보조기기까지 지원합니다.
- **결과보다 과정 중심:** 수익률 하나만 강조하지 않고 최대낙폭·변동성·체결비용·KOSPI 대비 성과를 함께 보여줍니다.
- **실패도 학습 데이터:** 거절된 주문과 오류 상태도 원인·request ID와 함께 남겨 사용자가 다음 행동을 알 수 있게 합니다.

## 프로젝트 소개

StockPilot은 주식을 처음 접하는 사용자가 실제 투자 서비스의 흐름을 안전하게 연습할 수 있도록 만든 모의투자 서비스입니다.

사용자는 Google 로그인 후 원화 `₩100,000,000`과 달러 `$100,000`의 가상자금을 받고, 실제 KIS 시세를 확인한 뒤 가상주문을 제출합니다. 체결 결과는 StockPilot의 PostgreSQL 원장에 기록되며, KOSPI 벤치마크·수익률 리그·투자일지·학습 미션으로 이어집니다.

```text
포트폴리오 · 체결 품질 · KOSPI 상대성과 확인
    ↓
투자일지 · 챌린지 · 수익률 리그로 복기와 성장
```

## 차별화 기능: 시장 타임머신

StockPilot은 과거 데이터를 단순히 보여주는 데서 끝나지 않고, 사용자가 실제로 판단을 내린 뒤 결과를 확인하도록 구성했습니다. 종목 상세 영역의 **시장 타임머신**을 열면 KIS 일봉 데이터에서 과거 체크포인트를 무작위로 골라 다음 10거래일을 잠급니다.

1. 체크포인트의 종가와 직전 5거래일 흐름만 확인합니다.
2. 전액 매수, 3회 분할 매수, 현금 대기 중 하나와 연습 금액을 선택합니다.
3. 선택을 확정하면 실제 과거 가격 경로로 최종 금액, 수익률, 최대낙폭, 최고·최저 하루 변동을 계산합니다.
4. 같은 구간의 다른 선택지와 나란히 비교하고, 결과를 공유할 수 있습니다.

모든 계산은 브라우저에서 수행되는 가상 시뮬레이션이며 주문 원장이나 실제 계좌를 변경하지 않습니다. 과거 결과는 미래 수익을 예측하지 않으며, 타이밍·분할·현금 보유의 차이를 체험하는 학습 도구입니다. 데이터가 부족하거나 KIS가 일시적으로 응답하지 않으면 자동으로 안내 상태로 전환합니다.

## 핵심 설계

### 1. 모의원장과 실시간 시세의 분리

KIS는 종목·시세·지수·뉴스 조회에만 사용합니다. 주문은 KIS 주문 API로 전송하지 않고 FastAPI가 PostgreSQL의 가상계좌·포지션·주문·감사 이벤트를 트랜잭션으로 기록합니다.

```text
KIS WebSocket/REST ──> Market Collector ──> Redis shared snapshot
                                      │
                                      ├──> 공개 시세·KOSPI API
                                      └──> 가상체결 엔진 ──> PostgreSQL 원장
```

### 2. KOSPI를 서비스 기준선으로 사용

KOSPI 지수는 단순 차트가 아니라 사용자의 투자 판단을 설명하는 기준선입니다.

- 최근 5·20거래일 시장 수익률 계산
- 일별 수익률 변동성 계산
- 상승장·박스권·하락장·변동성 확대 국면 분류
- 개인 포트폴리오와 같은 기간의 상대성과 계산
- 종목·수량·주문내역을 공개하지 않는 익명 비교

계산 로직은 `backend/app/services/benchmark.py`에 순수 함수로 분리해 API와 테스트에서 재사용합니다.

### 3. 체결 전 위험 통제

주문 접수 시점에 거래 모드, 장 운영 상태, 시세 지연, 주문금액, 일일 주문 수, 현금, 보유 수량과 중복 매도 가능 수량을 검증합니다. 실패한 주문도 거절 사유와 감사 이벤트를 남겨 재현 가능한 학습 기록으로 보존합니다.

#### 거래 전 4단계 안전 확인

주문 버튼을 누르면 바로 체결하지 않고 확인 시트를 한 번 더 보여줍니다. 사용자는 다음 네 항목을 직접 확인해야 하며, 매수처럼 보유 수량 검증이 필요 없는 경우에는 해당 항목을 자동 통과시킵니다.

1. **가상거래 확인:** 실제 증권계좌로 주문이 전송되지 않는다는 점을 확인합니다.
2. **시세·주문 방식 확인:** 마지막 갱신 시각과 시장가·지정가·조건부 주문 방식을 확인합니다.
3. **수량·금액 확인:** 수량, 기준 가격, 예상 주문금액을 다시 확인합니다.
4. **매도 가능 수량 확인:** 보유 수량, 대기 매도주문과 보호주문을 제외한 실제 매도 가능 수량을 확인합니다.

이 확인 절차는 모바일에서도 한 손으로 조작할 수 있는 체크 카드로 제공되며, 네 항목을 모두 선택하기 전에는 확정 버튼이 비활성화됩니다. 이를 통해 실시간 가격이 움직이는 상황에서의 오입력과 모의투자·실거래 오인을 함께 줄입니다.

### 3-1. 서버 기록 기반 모의투자 면허

- 브라우저 저장값이 아니라 챌린지, 체결, 투자일지, 보호주문, 일별 성과 스냅샷을 서버에서 조합합니다.
- 시장 탐색 → 리스크 조종 → 원칙 운용 → 포트폴리오 운용의 4단계와 12개 미션을 제공합니다.
- 수익률이나 거래 횟수만 보상하지 않고 손절 계획, 복기, 분산 경험과 최대낙폭 관리 습관을 함께 평가합니다.
- 기존 `/api/growth/overview` 응답에 면허 진행도를 포함해 성장 허브 첫 화면에서 추가 요청을 만들지 않습니다.

### 3-2. 금융기관 검토를 고려한 소비자보호 설계

- **수익률 비가중 안전점수:** 높은 수익이나 많은 거래를 점수로 보상하지 않고 계획, 손실 방어, 분산, 복기와 과매매 절제만 평가합니다.
- **설명 가능한 산식:** 5개 평가 항목의 현재 점수와 최대 점수, 평가 이유, 다음 행동을 사용자 화면에 그대로 공개합니다.
- **개인정보 최소수집:** 실제 은행 계좌번호·계좌 비밀번호를 받지 않으며 Google 로그인과 서비스 내부 가상원장만 사용합니다.
- **금융소비자 오인 방지:** 안전점수는 신용점수, 투자적합성 평가, 금융자격 또는 상품 추천이 아님을 화면과 API 응답에 명시합니다.
- **사전예방형 UX:** 주문 후 경고가 아니라 주문 전에 현금, 보유수량, 중복 매도, 시세 지연과 위험한도를 검증합니다.
- **감사 가능성:** 주문 접수·거절·체결과 운영자 조치를 감사 이벤트로 남겨 사고 원인을 재현할 수 있습니다.
- **접근성·모바일 대응:** 상태를 색상 하나로만 전달하지 않고 텍스트·아이콘을 함께 사용하며 작은 화면에서도 전체 지표를 읽을 수 있습니다.

> 이 저장소는 KB국민은행 또는 기타 금융기관과 제휴·승인된 서비스가 아닙니다. 특정 은행의 상표나 UI를 복제하지 않고, 금융교육·소비자보호·리스크 관리에 적합한 독립적인 모의투자 제품을 지향합니다.

### 4. 대규모 접속을 고려한 시장 데이터 처리

KIS 수집기·목표가 알림·보호주문 매처는 전용 `worker` 서비스에서 실행하고,
API replica는 짧은 요청 처리에 집중합니다. Redis lease·공유 캐시·WebSocket
fan-out을 사용해 여러 브라우저가 같은 종목을 요청해도 외부 API 호출과 JSON
직렬화를 반복하지 않도록 구성했습니다.

### 5. 사용자 증가를 대비한 운영 하드닝

- **공용 데이터 캐시:** 뉴스·일봉·기업정보는 서비스 캐시와 CDN `s-maxage`를 함께 사용해 방문자 수만큼 KIS·DART 호출이 늘어나지 않습니다.
- **초기 화면 경량화:** 차트 리플레이·공시·투자 도구·운영센터를 기능별 청크로 분리하고 화면 접근 직전에 불러와 첫 방문 JavaScript 실행량을 줄입니다.
- **실시간 렌더링 우선순위:** 1초 단위 시세 갱신은 React transition으로 처리해 검색·주문 입력이 먼저 반응하도록 구성합니다.
- **검색 체감 속도:** 검색 결과에 포인터·키보드 포커스가 도착하면 5초 TTL로 시세를 미리 요청하고, 선택 시 같은 요청을 재사용합니다.
- **검색 CPU 절감:** 전체 종목의 정규화 문자열을 적재 시 한 번만 만들고 `heapq.nsmallest`로 상위 결과만 선별해 대규모 종목 검색의 반복 정규화·전체 정렬을 제거합니다.
- **세션 요청 절감:** 사용자 프로필은 로그인 상태가 바뀔 때만 갱신하고, 10초 포트폴리오 폴링에서는 제외해 인증 API와 브라우저 작업을 줄입니다.
- **오프스크린 렌더링 절감:** 긴 종목·분석 영역은 IntersectionObserver와 `content-visibility`를 함께 사용해 보이지 않는 UI의 레이아웃·페인트 비용을 늦춥니다.
- **정확 조회 인덱스:** 종목 코드·시장·거래소 복합 키를 메모리 인덱스로 유지하고, 주문·알림·보호주문 상태 조회에는 PostgreSQL 복합 인덱스(`0012_scale_hot_paths`)를 적용합니다.
- **중복 워커 방지:** Redis lease로 알림·보호주문·시세 수집 리더를 한 인스턴스로 제한하고, 같은 종목의 워커 시세 조회도 poll 단위로 합칩니다.
- **장애 격리:** Redis가 잠시 끊겨도 로컬 fallback으로 읽기·로그인을 유지하되, 운영 워커 lease는 fail-closed로 중복 실행을 막습니다. readiness probe가 DB·Redis·시세 상태를 분리해 표시합니다.
- **시세 지연 격리:** KIS REST 슬롯을 제한 시간 안에 획득하지 못하거나 upstream이 느리면 사용자 요청을 빠르게 종료해 API worker가 무한 대기하지 않습니다. 오래된 시세로 주문을 체결하지 않는 정책도 유지합니다.
- **캐시 미스 single-flight:** 같은 키의 첫 갱신을 한 요청만 수행하고 다른 replica는 공유 결과를 기다려, 인기 종목의 동시 cache miss가 KIS 호출 폭주로 번지지 않게 합니다.
- **실시간 연결 보호:** WebSocket handshake에도 사용자/IP별 동시 연결 슬롯과 만료 lease를 적용하고, 브라우저는 지수 백오프·jitter로 재연결해 장애·새로고침 폭주를 흡수합니다.
- **부팅 경량화:** production API·worker는 컨테이너마다 migration을 실행하지 않습니다. 배포 전 one-shot migration을 완료한 뒤 readiness를 통과한 replica만 트래픽을 받습니다.
- **요청 보호:** 사용자/IP별 읽기·쓰기 rate limit과 API/nginx 본문 크기 제한을 적용하고, 모든 응답에 request ID·보안 헤더를 남겨 추적과 abuse 대응을 가능하게 합니다.

이 보호장치는 “무제한 트래픽”을 보장한다는 뜻이 아니라, 실제 사용자가 늘 때 외부 API·DB·워커가 먼저 무너지는 것을 막는 운영 기준선입니다. 배포 전에는 `docs/OPERATIONS_RUNBOOK.md`의 migration·백업·부하 점검 절차를 따라야 합니다.

### 결제 연동을 위한 준비 상태

현재 `backend/app/routes/billing.py`가 공개 요금제 카탈로그, 무료 권한 계약, Pro·Team 출시 알림, 결제 미설정 시 fail-closed 응답을 제공합니다.

- `GET /api/billing/plans`: 가격·기능·플랜별 한도와 결제 공급자 상태
- `GET /api/billing/entitlement`: 현재 계정에 서버가 부여한 플랜과 기능
- `POST /api/billing/interests`: 추가 개인정보 없이 Google 계정별 출시 알림 저장
- `POST /api/billing/checkout`: 결제 설정 전에는 503으로 차단하고, 향후 공급자 어댑터가 연결될 자리

실제 과금을 켤 때는 국내 결제 공급자 또는 Stripe 중 하나를 선택하고, 결제 승인·취소·환불 웹훅의 서명 검증과 idempotency를 먼저 구현해야 합니다. 결제 성공 화면만으로 권한을 주지 않고 검증된 서버 이벤트로 `subscriptions`와 `entitlements`를 갱신하는 것이 원칙입니다. 가격 변경, 해지·환불, 세금계산서, 개인정보 보관 기간은 사업자 요건을 확인한 뒤 별도 운영 정책으로 확정합니다.

| `POST` | `/api/league/rooms/{id}/challenge-orders` | 앱인토스 동일 시작금 친구 챌린지의 독립 가상주문 | 필요 |

투자 복기의 일별 성과 기록은 로그인 사용자가 웹 또는 앱인토스에서 `GET /api/trading/portfolio`를 조회할 때 서울 날짜 기준으로 갱신됩니다. 같은 날짜의 웹·앱 조회는 한 기록에 합쳐지며, 서로 다른 날짜의 기록이 2일 미만이면 최대 하락 폭은 `null`(기록 부족)입니다. 과거에 기록되지 않은 날짜의 수익률은 소급 생성하지 않습니다.
| `GET` | `/api/billing/plans` | 무료·Pro·Team 공개 상품 카탈로그 | 없음 |
| `GET` | `/api/billing/entitlement` | 서버가 부여한 현재 플랜·한도 | 선택 |
| `POST` | `/api/billing/interests` | 로그인 계정별 Pro·Team 출시 알림 등록 | 필요 |
| `GET` | `/api/billing/admin/interests` | 운영자용 플랜별 관심 수 집계(개인정보 미노출) | 운영자 |
| `POST` | `/api/billing/checkout` | 결제 공급자 연결 전 fail-closed 경계 | 필요 |
| `WS` | `/api/trading/ws` | 실시간 시세 스트림 | 없음 |

- Docker Desktop
- Git
- KIS Open API 키·시크릿(시세 연동 시)

### 커스텀 도메인

기본 운영 주소는 `https://stockpilot.coders.kr`이며, Coders.kr의 도메인 연결 기능으로
`stockpilot.kr`을 같은 프로젝트에 연결할 수 있습니다. 도메인 등록 후 발급된 소유권 TXT,
라우팅 A(또는 DNS 제공업체의 apex CNAME flattening), 인증서 DCV CNAME을 등록하고
`verify_domain`을 호출해야 인증서가 발급됩니다. 기존 주소와 데이터는 유지됩니다.

Google Cloud Console의 OAuth 클라이언트에는 다음 승인된 리디렉션 URI를 모두 등록해야 합니다.

```text
https://stockpilot.coders.kr/api/auth/google/callback
https://stockpilot.kr/api/auth/google/callback
https://www.stockpilot.kr/api/auth/google/callback
```

로그인 콜백은 허용된 호스트에서만 현재 호스트를 사용하며, 그 외 Host 헤더는 기존
`GOOGLE_REDIRECT_URI`로 되돌아가도록 구성되어 있습니다.

KIS는 시세 조회에만 사용하며, 실제 주문 API 자격증명은 이 프로젝트에 사용하지 않습니다.

StockPilot은 학습과 경험을 위한 가상투자 서비스입니다. 표시되는 시세는 데이터 제공자 정책과 네트워크 상황에 따라 지연될 수 있으며, 수익을 보장하지 않습니다. 실제 금융상품 매매나 투자자문 서비스로 사용하려면 별도의 법률·규제·보안·운영 검토가 필요합니다.

## 앱인토스 선택형 광고 · 새 연습 계좌

- 광고를 자발적으로 끝까지 본 뒤 **별도 연습 계좌**로 다시 시작합니다. 원화 1억 원·별도 USD 10만 달러를 서버에서 생성하며 실제 돈을 지급하지 않습니다.
- 원래 계좌·리그·친구 챌린지·웹 UI는 초기화하지 않습니다. 이전 연습 계좌도 기록을 보관하며, 보관으로 전환된 연습 계좌의 대기·보호 주문만 취소합니다.
- 기본 시세 조회·주문·설정·개인정보 삭제에는 보상형 광고를 요구하지 않습니다. 계좌 전환은 무료이고 새 연습 계좌는 경쟁 순위에 반영되지 않습니다.
- `GET /api/toss-practice/state`, `POST /api/toss-practice/rewards/prepare`, `POST /api/toss-practice/rewards/complete`는 Toss 세션만 허용합니다. 클라이언트가 원장 소유자를 지정할 수 없고, `X-Stockpilot-Practice: active`는 인증된 본인의 현재 연습 계좌로만 매핑됩니다.
- 이용권 예약·완료는 사용자별 DB 행 잠금과 동일 요청키·이용권의 멱등성으로 처리합니다. 완료 응답을 잃으면 같은 이용권으로 재확인하며 광고를 다시 요구하지 않습니다. 하루(KST) 3회·1시간 간격으로 제한합니다.
- SDK `userEarnedReward` 콜백은 서명된 서버 영수증이 아닙니다. 이 연동은 제한된 비현금·비경쟁 연습 혜택에만 쓰며, 유료 재화·현금·상금·리그 잔액 지급의 검증 수단으로 사용하지 않습니다. 실제 광고 정산은 광고망의 노출 기록과 사업자 승인에 따릅니다.
- Alembic `0017_toss_practice_rewards`는 새 테이블 3개와 인덱스만 추가합니다. 기존 사용자·투자 원장은 변경하지 않습니다. 다운로드·회원 삭제 범위에는 보관된 연습 원장도 포함합니다.

| 환경변수 | 목적 | 기본값 / 준비 |
|---|---|---|
| `TOSS_PRACTICE_REWARDED_GROUP` | 운영 보상형 광고 그룹 | 빈 값이면 신규 혜택 비활성. 앱인토스 콘솔에서 발급 |
| `TOSS_PRACTICE_ALLOW_TEST_ADS` | 공식 테스트 광고 허용 | `false`. 비공개 실기기 QA에만 임시 허용 |

검증: 프런트 단위·반응형·광고 실패 회귀와 백엔드 SQLite 트랜잭션 회귀를 실행합니다. SQLite 검사는 PostgreSQL 동시성 부하 인증을 대신하지 않으며, 네이티브 광고와 마지막 원장 반영은 토스 실기기에서 별도 확인해야 합니다. 앱인토스 클라이언트 소스·AIT 번들은 이 공개 저장소에 추가하지 않습니다.
