# 2026-11-07 웹 출시 전 고도화·배포 점검

## 범위와 승인

사용자의 `배포 및 고도화` 요청으로 기존 코더스 웹의 GitHub 반영·실제 포크 동기화·재배포가 승인됐다. Nov6 미배포 개선과 이번 출시 전 결함 수정을 대상으로 한다. 기존 디자인·계좌·주문 금액 계산·앱인토스·사용자 LeagueRooms 변경은 유지한다. 계좌 초기화, 운영 부하 시험, 유료 자원 생성은 수행하지 않는다.

## 출시 전 보완

- 원화 가격 입력의 `min=0.01`, `step=1` 불일치: 정수 원화 목표값이 브라우저에서 거부될 수 있어 원화 최소값은1, 달러는0.01로 정렬한다. 서버 금융 검증·계산은 그대로다. [MDN number input의 step 기준](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/number#step)을 확인했다.
- 비교 메모를 확인된 저장 계정에 묶고 계정 변경 후 이전 개인 초안·늦은 저장 완료 안내가 남지 않게 한다. 공개 종목 선택/비교 기간은 유지한다.
- 저장 요청의 선택적 `X-StockPilot-Owner`와 인증된 계정이 다르면 쓰기 전에 거부한다. 프런트는 이전 계정 목록을 비우고 읽기만 재조회하며 쓰기를 자동 재전송하지 않는다. 기존 헤더 없는 클라이언트는 호환한다.
- 투자 도구의 리포트에도 원가 대체·종목 정보 누락 상태를 명시한다. 기존 숫자는 바꾸지 않고 불완전한 현재 수익률/가격 흐름을 확정 정보로 표시하지 않는다. 체결 기반 통계는 유지한다.
- 브라우저에서 빠른 검색을 Escape로 닫을 때 초점이 사라지는 문제를 재현했다. 입력의 중복 자동 포커스를 제거하고 공통 대화상자 훅이 초점을 관리하게 했다. 수정 빌드에서 입력→닫기 버튼→입력→검색 버튼 복귀를 확인했다.

## 검증 결과

- 별도 후보 디렉터리에서 검증했다. 사용자 리그 변경과 로컬 산출물은 포함하지 않았다.
- 백엔드: `python -m pytest unit_tests -q -p no:cacheprovider` 308개 통과. 기존 Firebase `MulticastMessage.tokens` 사용의 deprecation 경고 3건이 남아 있다.
- 프런트: `verify:safety` 27개 검사 스크립트, `verify:product` 11개, TypeScript, 변경 파일 ESLint/Ruff 통과. 검색 초점 수정 후 해당 회귀 6개를 재실행하고 Next.js webpack 프로덕션 빌드·타입 검사·정적 26페이지 생성을 다시 확인했다.
- 브라우저: 작업 설정 재시도 후 연결이 복구됐다. 정적 빌드에 격리된 읽기 응답을 공급하고 운영 API를 연결하지 않았다. 전체 종목 화면은 360×800, 390×844, 768×1024, 1440×900에서 밝은/어두운 테마 모두 페이지 가로 넘침이 없었다. 실제 PC·모바일·태블릿 화면을 캡처해 헤더·목록·글자색과 모바일 하단 탐색·주문 창을 확인했다.
- 종목 흐름: 다음 페이지의 21–40번째 목록을 열어도 기존 비교 선택이 유지된다. 미국 검색 조건을 브라우저에 저장하고 국내·미국 종목을 비교했다. 1주/1개월 전환과 뒤로가기, 날짜 키보드 조작, 서로 다른 통화 단위 표시를 확인했다. 빠른 검색으로 상세 이동 뒤 기존 미국 검색 조건으로 돌아왔다.
- 내 기록 흐름: 알림 10건에서 읽지 않은 도달과 티커를 조합해 조회했다. 실제 브라우저의 원화 목표가 73,000원과 지정가 71,999원은 `min=1`·`step=1` 유효성 검사를 통과했다. 시세 누락 리포트가 수익률은 보류하고 체결 통계·참고액은 표시했다. 보유 화면은 참고액/손익 확인 불가를 명시했다. 캘린더에서 체결 내역으로 들어갔다가 같은 월·날짜로 돌아왔다.
- 검증 범위: 브라우저에서 실제 주문·저장·알림 발송을 하지 않았다. 쓰기 검증은 격리 자동 테스트로 수행했다. 관찰한 주요 브라우저 흐름의 콘솔에서 오류/경고가 없었다. 실제 운영 사용자 인증·시세·부하 수치는 이 로컬 결과에 포함되지 않는다. Nov6 결과는 [별도 검증 기록](web-upgrade-qa-20261106.md)에 보존한다.

## 남은 확인과 배포 상태

사전 점검에서 Coders 프로젝트의 자동 배포 브랜치는 `main`이고 원본 저장소에 Coders GitHub App이 설치되어 있었다. [Coders 플랫폼 문서](https://github.com/coders-kr/template-coders/blob/main/PLATFORM.md#10-push-to-deploy-optional)에 따르면 푸시 시 새 배포가 먼저 시작될 수 있다. 기존 정책의 원본→포크 동기화→배포 순서를 유지하려면 자동 배포를 일시 중지하거나, 사용자가 이번 릴리즈에 한해 순서 예외를 명시적으로 승인해야 한다.

원본 푸시 전 후보를 검증한 기록이다. 운영 전환은 새 배포의 식별자와 `ready` 상태, 양쪽 `main`의 동일 SHA, 공개 화면을 별도로 확인한다. 기존 배포의 `ready`나 HTTP 200은 이 버전의 운영 반영을 뜻하지 않는다.
