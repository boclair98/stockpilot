# 증권사 도입 준비 기준

## 현재 제품의 정확한 위치

StockPilot은 **실시세 기반 모의투자·고객교육용 화이트라벨 파일럿**입니다.
가상 원장, 주문 검증, 검색·분석, 투자일지, 리그와 운영 기반을 갖췄지만
실제 고객 자산을 보관하거나 거래소에 실주문을 전송하는 증권 원장은 아닙니다.

| 도입 시나리오 | 현재 판단 | 비고 |
|---|---|---|
| 사내 데모·사용성 검증 | 가능 | 운영 URL과 테스트 계정으로 즉시 시연 가능 |
| 고객 교육·모의투자 파일럿 | 조건부 가능 | 데이터 계약, 보안 검토, 부하시험 후 제한 고객 대상 |
| 증권사 브랜드 화이트라벨 | 추가 개발 필요 | 테넌트·관리자·브랜드 설정, 사내 IAM 연동 필요 |
| 실제 고객 돈을 쓰는 매매 | 불가 | 라이선스·실주문 OMS/원장·규제 통제·외부 인증 필요 |

## 이번 코드에 적용된 통제

- `Idempotency-Key`와 DB 유일 제약으로 재전송·중복 클릭의 이중 체결 방지
- 같은 키에 다른 주문 내용을 넣으면 409로 차단하는 요청 지문
- 접수·트리거·체결·거절·취소를 남기는 append-only 감사 이벤트
- 계좌·포지션·대기 주문의 DB 행 잠금과 단일 트랜잭션 처리
- 요청 ID, 처리 시간, 상태 코드 집계, liveness/readiness 분리
- Redis 기반 분산 캐시·요청 제한과 장애 시 명시적 degraded 상태
- API·SPA 보안 헤더, 비밀값의 환경변수 분리, 비루트 컨테이너
- GitHub Actions의 백엔드 테스트·정적 분석 및 프런트 린트·빌드 게이트

## 증권사 파일럿 전 필수 게이트

### 1. 사업·계약

- KIS·거래소·뉴스·기업 로고의 기업용 이용 및 재배포 권리 서면 확인
- 서비스가 모의투자인지 투자자문·일임 또는 전자금융업에 해당하는지 법률 검토
- 개인정보 처리위탁, 국외 이전, 보존·파기 정책과 고객 고지 확정
- 장애·데이터 오차·모의 체결 기준을 포함한 SLA와 책임 범위 합의

### 2. 보안

- SAST, 의존성·컨테이너 스캔, 침투 테스트와 조치 결과 검증
- 관리자 MFA, 최소권한 RBAC, Secret Manager/KMS, 정기 키 교체
- 감사 로그를 별도 WORM 저장소/SIEM으로 실시간 반출하고 접근 자체도 감사
- ISMS-P 및 적용되는 전자금융감독규정 통제에 대한 독립 심사

### 3. 신뢰성

- 예상 피크의 2배 이상 부하·소크 테스트와 DB 잠금 경합 시험
- 다중 가용영역, 자동 백업 복구 훈련, RTO/RPO 승인
- 시세 지연·오류·단절 시 주문 정지 및 사용자 고지를 담당하는 market-data circuit breaker
- SLO 예시: 월 가용성 99.9%, 주문 API p95 500ms 이하(외부 시세 정상 시), 중복 체결 0건

### 4. 실거래로 확장한다면

현재 가상 원장을 실거래에 재사용하지 않습니다. 증권사 내부 OMS/계정계와 승인된
전용망·메시지 규격으로 새 어댑터를 만들고, 사전 주문 위험관리, 정정·취소, 체결
대사, 예수금·미수·권리·세금, 거래소 세션, KYC/AML, 이상거래 탐지, 재해복구를
별도 설계해야 합니다. 이 단계는 증권사 보안·준법·리스크·IT 부서의 공동 승인이
필수입니다.

## 권장 도입 순서

1. 익명 사내 데모
2. 사내 임직원 모의투자(개인정보 최소화)
3. 부하·보안·복구 시험
4. 제한 고객 교육 파일럿
5. 화이트라벨·사내 IAM·운영자 콘솔 연동
6. 외부 감사 후 정식 모의투자 서비스

각 단계는 이전 단계의 증적과 잔여 위험 승인이 있어야 다음 단계로 진행합니다.
