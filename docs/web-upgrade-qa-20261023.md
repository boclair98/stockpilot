# 웹 일상 투자 흐름 고도화 검증 · 2026-10-23

## 범위와 배포 상태

코더스 StockPilot 웹의 기존 디자인·계좌·주문 계산·API 계약을 유지한 개선이다. 앱인토스 소스와 번들은 변경하지 않았다. 신규 DB 마이그레이션·의존성·자격증명은 없다. 이 문서는 **GitHub 게시·운영 배포 전 수행한 검증 기록**이다. 사용자는 2026-10-23 GitHub 반영·포크 동기화·웹 배포를 승인했다. 배포의 최종 상태와 운영 검증은 별도로 확인해야 한다.

## 확인한 개선

- 보유 주식: 회사명·코드 검색, 한국·미국 필터, 수익률·이름 정렬, 20개씩 더보기, 기존 종목 상세로 이동. 원본 보유 배열을 변경하지 않는다.
- 투자 점검: 통화별 비중·현금·보호 범위를 계산하고, 중복 보호량을 실제 보유량으로 제한한다. 자산이 없는 통화는 100%나 0%로 만들지 않고 대시를 표시한다.
- 검색·시장 목록: 오래된 응답 무시, 한글 조합 중 Enter 보호, 종목 변경 시 주문 초안 분리, 다음 페이지 오류 후 기존 목록 유지·해당 커서 재시도.
- 분석·계좌 명세: 시간 제한·응답 검증·재조회·로그인 안내. 실패한 조회를 초기 잔액이나 0원으로 표시하지 않는다. 일별 분석은 실제 응답 자료의 표로도 제공한다.
- 알림: 제한된 묶음의 순환 처리, 오래되거나 잘못된 시세 제외, 개별 종목 오류 격리, 앱 내 알림 평가와 Firebase 전송 분리, 전송 시간 제한.
- 개인 기능: 환전·정기매수·문의의 미확정 요청 키 보존, 잘못된 HH:mm 거부, 서울 시간 표시.

## 자동 검사

- Next.js 프로덕션 빌드: 컴파일·TypeScript·24개 정적 경로 생성 성공(Node 24).
- `frontend`의 `verify:safety` 8종 성공: release-safety, comparison, market-responses, record-filters, market-navigation, portfolio-insights, analytics-recovery, personal-write. 최종 변경 후 8종을 모두 다시 실행해 성공했다.
- 신규·수정 프론트 컴포넌트와 helper의 범위 지정 ESLint 성공. 저장소 전체가 lint-clean하다는 주장은 아니다.
- `backend`: `python -m pytest unit_tests/test_alert_safety.py unit_tests/test_investor_tools.py tests/test_personal_tools.py -q -p no:cacheprovider` — 63개 성공. SDK의 기존 `tokens` 사용 중단 예정 경고 3개는 실패가 아니다.
- 수정 백엔드 파일 범위의 Ruff 성공.

## 실제 브라우저 확인

운영 계좌나 외부 시세에 시험 주문을 만들지 않도록 `UPGRADE_FIXTURE=1`인 격리된 로컬 서버에서 수행했다. 모든 화면의 금액·종목·지수는 **검증용 자료**이며 실제 시장 자료가 아니다. 이 서버는 운영 백엔드와 DB에 연결하지 않는다.

- 보유 목록 25개: 처음 20개 → 더보기 25개, AAPL 검색, 검색 결과 없음 → 전체 복구, 미국 8개 필터, 수익률 정렬, 삼성전자 상세 URL의 시장·거래소·코드 확인.
- 보유 화면: 360×800 다크, 390×844 라이트, 768×1024 다크, 1440×900 라이트·다크를 직접 확인했다. 해당 크기에서 페이지 가로 넘침이 없었다. 새 필터·목록·고정 하단 메뉴의 겹침을 점검했다.
- 전체 종목 목록: 20개 → 의도한 다음 페이지 503 → 기존 20개 유지 → 재조회 40개 → 마지막 45개, 마지막에는 더보기 종료.
- 분석: 의도한 503 → 다시 조회 → 정상 지표, 일별 표의 날짜·누적 수익률·이전 기록 대비 %p 확인. 잘못된 숫자 응답·빈 기록·비로그인 응답도 확인했다. 390px 표에서 가로 페이지 넘침이 없었다.
- 계좌 명세: 의도한 503에서 미확인 잔액을 숨김 → 재조회 후 확인된 원화 7,500만원/달러 9만 현금과 각 통화 총자산 표시(검증용 값).

스크린샷은 `frontend/artifacts/web-upgrade-*.jpg`에 로컬로 보관했다. `artifacts/`에는 기존 사용자 파일도 있으므로 일괄 게시하거나 삭제하지 않는다.

## 확인 범위의 한계

- 격리 서버에서 제공하지 않는 성장 허브·일부 보조 API는 의도적으로 404이다. 이것을 운영 API의 장애나 전체 콘솔 무오류 검증으로 해석하지 않는다.
- 실제 Google 로그인, 운영 Firebase 전달, 실기기 푸시, 운영 DB, 장중 시세 지연, 대규모 부하, 실제 스크린리더·확대 글꼴 전 구간 검증은 이번에 수행하지 않았다.
- 브라우저 도구의 간헐적 응답 지연이 있어 재연결 후 검증했다. 도구 지연을 서비스 성능 측정값으로 사용하지 않았다.
- 장애가 절대로 없거나 특정 동시접속 규모를 견딘다는 보장은 하지 않는다. 운영 배포 승인 시 upstream → 실제 fork 동기화 → 코더스 배포 → 운영 화면·health 확인을 별도로 수행해야 한다.
