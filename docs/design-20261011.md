# StockPilot · Fresh, Friendly, Precise

2026-10-11 코더스 **웹** 개편 기록. 앱인토스 비공개 소스·번들·광고 그룹, 원장, 계좌 및 DB 스키마를 수정하지 않습니다. 이 문서는 자동 생성한 품질 점수나 출시 보증서가 아닙니다.

## 확인한 기준선

Next.js 16.2.2 / React 19.2.4 정적 export, Tailwind 4와 프로젝트 CSS, Lucide, 직접 작성한 SVG 차트입니다. 인증은 기존 Google OAuth HttpOnly 세션, 가격은 bootstrap / WebSocket / 개별 quote API, 계좌·주문은 기존 FastAPI 계약을 유지합니다. 2026-10-11 운영 홈을 1440·390px에서 HTTP 200, pageerror 없음으로 확인했습니다. 큰 자동 전환 소개 배너가 첫 데스크톱 화면 대부분을 차지해 종목과 차트가 화면 아래에 있었습니다. 인증된 운영 계좌를 열었다고 주장하지 않습니다.

기존 `/`, `/learn`, `/league`, `/practice`, `/growth`, `/lounge`, `/pricing`, `/profile`, `/guide`, `/privacy`, `/terms`, `/account-deletion`, `/operations`를 유지합니다. 주요 계좌·관심·기록은 홈 hash / query로 연결합니다. 시가총액·거래량·상승/하락은 이미 배포된 공개 읽기 API를 사용합니다. ‘사용자 인기’로 거래량을 오인하지 않습니다.

## 디자인 결정

- **시장 홈**: 종목 탐색 7 : 개인 맥락 5. 브랜드 민트의 실제 KOSPI 요약과 읽기 편한 공통 종목 행, 관심종목·이어보기. 캠페인 캐러셀을 기본 투자 화면에서 제거했습니다.
- **종목 상세**: 중앙 차트와 320~350px 주문 패널. 모바일에서는 차트 중심 단일 열 + 명시적으로 여는 주문 시트. 수신 중에 수량·희망가를 덮어쓰지 않습니다.
- **관심·자산·기록**: 일관된 화면 언어와 자연스러운 한국어 메뉴. 판단 메모는 이 브라우저만의 저장임을 표시합니다. 서버 주문 기록과 개인 메모를 구분합니다.
- **정확성**: 원화·달러를 환율 없이 더하지 않습니다. 실제 돈이 아닌 모의 주문임을 유지합니다. 자료 미제공·지연·실패는 0이나 가짜 종목으로 채우지 않습니다. 연결 상태를 실시간 데이터 신선도로 오인하지 않습니다.
- **모션**: 누름·선택·시트 진입에만 짧은 CSS 피드백. 숫자 count-up·반복 펄스·자동 순위 섞기 없음. reduced-motion 지원. 금융 상태 전환에 새 View Transition 의존성을 도입하지 않았습니다.

## 검증 방식과 한계

`frontend/scripts/verify-workspace.mjs`는 localhost만 허용하고, 모든 API 쓰기를 격리 fixture로 처리합니다. 검색 → 종목 상세 → 관심 저장 → 모의 주문 확인 → 상태·보유 → 개인 메모를 반복합니다. 실제 운영 계좌 주문은 하지 않습니다. 개발 서버에서 8개 폭(320/360/390/430/768/1024/1440/1920) 88개 흐름 검사와 pageerror 0을 확인했습니다. 프로덕션 export에서 추가 상태·확대·뒤로/앞으로·세션 만료 검사를 수행합니다. 최종 결과는 배포 보고에 별도로 기록합니다.

세 번의 시각 수정: ① 터미널 대신 발견/상세 구도와 민트 정체성 ② 중복 모바일 필터·과도한 여백·행 정렬 ③ 작은 폭의 저장 버튼·확대 시 고정 최소 폭·다크 대비·기록과 포커스 연속성. 수정 전후 이미지를 직접 확인했습니다. 테스트 화면의 검증 종목과 금액은 운영 시세를 대신하지 않는 격리된 UI 예시입니다.

최종 정적 빌드에서는 Chromium/WebKit 각각 128개 검사를 통과했습니다. 8개 폭, 125% CSS 확대 스트레스, 검색 빈 결과/실패, 세션 만료, 뒤로·앞으로, 모바일 자산·기록 메뉴를 포함합니다. 격리 API 검사는 서비스워커를 차단하며 PWA 산출물은 별도 검사로 확인합니다. 타입·변경 컴포넌트 ESLint·Next 정적 빌드(19개 출력)·PWA 검사 통과. 이번에는 서버 소스 변경이 없고 관련 주문/체결/모의 규칙 8개 테스트가 통과했습니다. 전체 서버 suite는 이 환경에서 일부 진행 후 멈춰 종료했으므로 전체 112개 통과라고 주장하지 않습니다.

LCP/INP/CLS의 실사용 p75 자료는 없습니다. 로컬 개발 서버+fixture에서 초기 목록 준비를 1.33~2.03초로 관측했지만 이것은 LCP나 실사용 INP가 아닙니다. 성능 목표는 [Core Web Vitals](https://web.dev/articles/vitals)의 정의에 따라 필드 데이터와 분리합니다. 접근성은 [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/)를 기준으로 확인하되 전체 인증을 주장하지 않습니다.

## 실행

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
node scripts/verify-pwa.mjs
node scripts/preview-export.mjs
# 별도 터미널: Playwright 설치 후
STOCKPILOT_VERIFY_URL=http://127.0.0.1:5191 node scripts/verify-workspace.mjs
```

테스트는 Playwright가 필요하며 프로젝트 의존성을 바꾸지 않고 `STOCKPILOT_PLAYWRIGHT`에 설치된 모듈 경로를 지정할 수 있습니다. `STOCKPILOT_VERIFY_OUTPUT`은 스크린샷·검증 결과의 출력 디렉터리입니다. 실기기 키보드·실제 Google OAuth 전체 로그인·운영 사용자 개인 계좌는 별도 사용자 확인 범위입니다. 없는 API를 새로 받아야 이번 디자인이 실행되는 것은 아닙니다.
