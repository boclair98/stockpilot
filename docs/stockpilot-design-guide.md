# StockPilot 웹 디자인 지침

StockPilot은 시세를 읽고 판단한 뒤 모의계좌에서 연습하는 작업 공간이다. 화면의 목표는 ‘종목 찾기 → 시세의 의미 판단 → 모의주문 확인 → 결과와 판단 복기’다. 투자 조언이나 실제 체결을 약속하지 않는다.

| 화면 | 첫 번째로 읽거나 할 일 | 보조 요소 |
| --- | --- | --- |
| 시장 | 검색과 국내·미국 종목 비교 | PC는 옆에 지수·자산·관심종목, 모바일은 종목 목록 뒤 |
| 종목 상세 | 이름·시장·거래소·통화 → 가격·등락·시세 기준 → 차트 | 저장·알림은 작은 보조 동작, 기업·공시·복기는 차트 뒤 |
| 모의주문 | 매수/매도 방향, 수량, 주문 종류, 예상 금액, 확인 | 실제 자금이 아님을 명시하고 확인 전 전송 금지 |
| 자산·기록 | 금액의 통화와 평가 기준, 주문의 실제 처리 상태 | 기간·필터·복기는 검증 가능한 기본 정보 뒤 |

## 표현과 반응형

- 기존 Pretendard와 시스템 산세리프를 유지한다. 가격은 표 너비가 안정적인 숫자, 이름은 한국어 글줄을 먼저 배려한다. 종목 상세 기준 이름은 21–28px, 가격은 30–44px, 상태는 12–13px로 역할을 나눈다. 중첩 테두리 대신 8/12/16/24px 간격과 구분선으로 정보 묶음을 보여준다.
- `--ws-canvas`, `--ws-surface`, `--ws-ink`, `--ws-muted`, `--ws-line`으로 두 테마를 맞춘다. 인디고 `--ws-brand`는 선택·포커스·탐색에, `--ws-up`·`--ws-down`은 확인된 가격 변화에만 쓴다. 등락은 부호·문구를 함께 표시한다. 상태·강조·오류를 색 단독으로 전달하지 않는다.
- PC는 분석과 기존 주문서를 나란히 보이게 한다. 작은 화면에서 오른쪽 패널을 그대로 줄이지 않는다. 시세와 차트를 먼저 읽고 기존 모바일 주문 진입점 하나를 이용한다. 44px 조작·보이는 포커스·시트 포커스 복귀·하단 안전 영역을 지킨다.
- 가격 없음은 `—`이며 0이나 상승으로 보이지 않게 한다. 로딩과 실패, 재조회, 과거/지연/최근 조회 표시는 서로 구분한다. 조회 시각과 체결 시각을 섞지 않으며 공급 범위나 거래 가능 여부를 확대 해석하지 않는다. 매수/매도·접수/체결·취소·불확실도 구별한다.
- 장식용 캠페인, 임의 지표, 가짜 차트, 무관한 사진을 시장과 상세 위에 올리지 않는다. 모션은 조작 상태를 이해시키는 경우만 사용하고 reduced motion을 존중한다. 기존 브랜딩·API·Next.js/FastAPI·계좌와 별도 앱인토스 계약은 그대로 둔다.

## 근거와 검증

- 현재 공개 제품의 한국어 종목 상세·차트·주문의 정보 위계를 먼저 관찰한다. 관찰 화면, PC·모바일 차이, 채택·제외 항목은 [설계 기록](../design.md)에 적는다. 이름·문서만 보는 것은 시각 검토가 아니다.
- 외부 시안은 공개 종목명 등 비식별 자료로만 만들고 모의 숫자와 가짜 거래를 운영 근거로 쓰지 않는다. 운영 제품 코드에 그대로 삽입하지 않는다.
- 360·390·768·1440px, 두 테마, 긴 이름·거래소·통화, 상태 실패 후 재시도, 차트와 주문 시트의 키보드·안전 여백을 확인한다. 계좌와 주문 결과는 격리 자료로만 테스트한다. 로그인된 운영 계좌의 포트폴리오 조회는 주문 처리에 영향을 줄 수 있어 운영 점검에서 호출하지 않는다.
