# 웹 기능 고도화 점검 · 2026-10-25

## 범위와 보존

코더스 StockPilot 웹만 변경했다. 앱인토스 번들·검토 상태, 기존 웹 브랜드/색상/계좌 데이터/주문 규칙은 유지한다. 사용자 작업인 `LeagueRooms.tsx`와 기존 `frontend/artifacts`는 커밋 대상에서 제외한다. DB 마이그레이션·자격증명·환경변수·요금제 변경은 없다.

## 구현 및 확인한 계약

- 새 인증 읽기 API `GET /api/trading/activity?month=YYYY-MM`: 한 달의 체결을 SQL 날짜×통화 집계(최대93그룹)로 계산한다. 본인 선택 원장만 조회하며 `private, no-store`를 사용한다. 월 형식/범위를 제한하고 미래 시각과 다른 계정의 주문을 제외한다.
- 실제 `processed_at`이 없는 과거 기록은 `created_at`으로 대체하고 그 건수를 알린다. 통화가 확인되지 않는 기록은 금액에 임의 합산하지 않는다. 없는 체결가·비용·실현손익은 null로 구분한다.
- 기존 기록 API의 기본 주문일 동작을 유지하고 `dateBasis=execution`을 추가했다. 캘린더 날짜→체결일 필터→상세/CSV까지 같은 날짜 기준을 유지한다. CSV는 불러온 기록만 내려받고 수식 삽입을 차단한다.
- 계좌 명세의 주문 누계는 전체 SQL 집계, 보유 평가는100행 단위 키셋 조회로 계산한다. 응답 보유 목록은100개까지이며 전체 개수/더보기 여부를 분리한다. 기존 수신 시세를 사용하며 종목별 외부 HTTP 요청을 늘리지 않는다. 시세 미확인/비정상 가격의 매입금액 대체 평가를 표시하고 부분 자료에 리밸런싱 제안을 하지 않는다. 명세 평가를 현재 시세의 실시간 보증으로 표시하지 않는다.
- 이미 발급한 FX견적의 동일 요청번호 재확인은 외부환율 장애와 무관하게 같은 결과를 반환한다. 다른 금액의 같은 번호는409로 거부한다. 환전 원장/중복 출금 규칙은 유지한다.
- 정기매수 종목 변경 시 예산 초기화, 검색 중 이전 선택 등록 차단, 통화 정밀도/현지 시간 검증, 등록 전 내용 확인을 추가했다.
- 개인 조회10종의 구조를 검사하고 오류/빈 기록/이전 기록을 구분한다.401/403/비인증 계좌 응답은 개인자료를 숨긴다. 정상 DART nullable 필드는 원문 링크와 함께 허용한다.

## 실행 검사

- 최종 프론트 안전성 검사10종 모두 통과. 캘린더 helper/component3개, 개인 복구6개, 분석/명세/기록 연결10개 사례를 포함한다. 마지막 체결일 표시 변경 후 전체 검사를 재실행했다.
- 캘린더/기록 백엔드35개와 명세·환전·개인기능·주문·알림 회귀78개, 중복 없이 총113개 통과.78개에는 신규 명세/환전9개가 포함된다. 운영 DB/브로커 호출을 쓰지 않는 SQLite+ASGI 테스트이다. 기존 Firebase DeprecationWarning3건은 남아 있다.
- 새/변경 파일 대상 ESLint/Ruff 및 diff 공백 검사를 수행했다. 기존 전체 저장소 lint 무결성을 주장하지 않는다.
- Windows 테스트 환경의 asyncio 로컬 loopback 제한으로 초기 테스트가 정지했다. 동일 격리 검사를 로컬 loopback이 허용된 실행에서 수행해 통과했다. 운영 연결이나 보안 검증을 생략하지 않았다.
- 실화면 보완 뒤 최종 Next.js16.2.2 프로덕션 빌드와 TypeScript,24개 정적 경로 출력까지 통과했다.

## 브라우저 검사

`UPGRADE_FIXTURE=1 PORT=5258 node scripts/preview-functional.mjs`의 명시적 격리 자료를 사용했다. 운영 API/계좌와 연결하지 않는다. 이 자료의 시세·지수·잔고·주문은 실제 시장/사용자 기록이 아니다.

-360×800 다크,390×844 라이트,768×1024 다크,1440×900 라이트 캘린더를 직접 관찰했다. 페이지 가로 넘침 없이 날짜/버튼/요약을 읽고 조작할 수 있었다.
- 월 이동→빈 달, 날짜 선택→통화별 요약→같은 날짜의 체결3건 조회를 확인했다. 주문일과 체결일이 다를 때의 목록 날짜는 추가 보완했다.
- 의도적503→재조회 성공, 손상 응답→명시적 오류, 개인 응답 손상→재조회 가능한 화면 유지 확인.
-390px 정기매수에서 삼성전자+10,000원→새 검색 중 등록 차단→애플 선택시 예산 빈값→50.25달러/뉴욕10:00 내용 확인을 관찰했다. 등록은 실행하지 않았다.
- 최종 빌드에서 키보드 Enter로 날짜 선택→상세 목록 전환을 확인했다.21/22일에 접수하고23일 체결된 격리 기록은23일 체결일로 표시되며, 전환 후 `investment-history-title`로 포커스가 복귀한다.
- 공통 금액 가리기 설정으로 캘린더 요약 금액에 `blur(7px)`가 적용되는 것을 확인하고 원래 표시 상태로 복구했다.
- 1차 운영 검증에서 발견한 비로그인 캘린더 안내 카드의 좌우 여백을 명시적으로 보완했다. 기능/집계 변경 없이 카드 본문과 로그인 버튼이 테두리에 붙지 않도록 했다.

## 게시 및 남은 한계

사용자가 이번 변경의 배포를 요청했다. 게시 순서는 `boclair98/stockpilot` 원본→실제 `coders-kr/stockpilot` 포크 동기화→동일 full SHA 확인→기존 Coders 프로젝트 재배포→ready/운영 화면 확인이다. 이 문서는 개발 점검 기록이며 작성만으로 게시가 완료됐다는 뜻이 아니다. 최종 배포 ID·SHA·운영 확인 결과는 완료 보고와 로컬 릴리스 영수증에 남긴다.

실제 Google 로그인, 실제 푸시 전달, 운영 계좌의 쓰기/환전/정기매수 실행, 실제 다중 사용자 고부하, PostgreSQL 동시성 부하와 네이티브 앱인토스 기기 동작은 이 검증에 포함되지 않는다. 테스트 통과가 장애0건·무제한 트래픽 수용의 보장은 아니다.
