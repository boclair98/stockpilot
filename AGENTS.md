# StockPilot contributor instructions

Preserve the Next.js static-export frontend, FastAPI APIs, existing accounts,
financial rules, and user changes. The separate Apps in Toss frontend is private;
web UI tasks do not authorize publishing or modifying it.

<!-- openui:start -->
## Mandatory OpenUI workflow

Use the installed `openui` skill for landing, home, marketing, hero, design-concept,
and multiple-variant page work. Before implementation, write repository-root
`design.md` with resolved inputs, a composition contract, the filled generation
prompt, output paths, real content, responsive behavior, and validation steps.
Preserve unrelated existing plans and explicit user design choices.

Resolve Topic, Offer, Audience, Primary user action, Deliverable, Style direction,
Tonal key, Icon policy, Proof assets, and Motion intensity. No placeholders or
invented metrics, testimonials, screenshots, prices, or integrations.

Produce one coherent result unless another number is requested. Multiple variants
must differ in composition and concept, not merely palette or copy. For four or
more, implement and inspect batches of at most three; compare every result.

Implement actual navigation, forms, and relevant states. Preserve API and auth
contracts. Run meaningful checks, inspect desktop and mobile screenshots,
keyboard focus, wrapping, contrast, and overflow. Respect reduced motion.

The product's working market screen takes priority over marketing decoration.
Do not place a full-screen campaign hero ahead of the stock list. Public sharing
must never include personal account data by default.

Repository linkage alone does not authorize commit, push, or deployment. When
publication is requested, follow the user's canonical boclair98 upstream → actual
coders-kr fork synchronization → existing Coders deployment → live verification
workflow. Keep unrelated user changes out of the publication.
